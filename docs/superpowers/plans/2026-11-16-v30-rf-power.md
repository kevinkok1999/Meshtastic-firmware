# V30 RF, power and extensibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve reliable communication per legal milliwatt; prevent map or optional features starving radio.
**Architecture:** A shared dispatcher-boundary ledger and fair scheduling guard all physical attempts; measurements drive channel/antenna decisions; capability-gated alternate transports follow the foundation.
**Tech Stack:** C++/Arduino ESP32-S3, SX1262, host C++ simulator, measured HIL
**Spec:** `v30/MASTER_SPEC.md`

## Global Constraints
- Preserve V29 artifacts, native chat, P1 V8 baseline and existing flash partition offsets. Stock T-Deck Plus, no mandatory SD, Internet or phone.
- No production publication or unsupported claims; CI evidence is not HIL, RF compliance, runtime or commercial approval.
- Use fresh failing executable tests first; independently verify full applicable suite. Use exact baseline pins in spec.

## Review Focus
- Power cycle or timeout cannot reset rolling transmit budget.
- Weak-link adaptation cannot break shared channel or P1 compatibility.
- Optional spectrum sweep, maps and portal cannot starve mesh RX.
- Energy estimates separate actual whole-board Wh from protocol TTL.
- Alternate transport retry cannot create duplicate or unsafe plaintext.
