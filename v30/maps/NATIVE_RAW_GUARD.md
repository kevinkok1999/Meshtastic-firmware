# V30 raw-map partition guard (development)

The pinned WadaMesh mount path had three automatic format opportunities (begin(true), explicit format on failure, reformat after invalid volume size). A padded MMN1 partition image is deliberately not LittleFS; that boot behavior would erase it. V30 now classifies just four bytes in the exact stock tiles partition and only mounts legacy candidates with formatOnFail=false. Missing/corrupt/raw images never trigger formatting in this path. Valid older LittleFS caches can still be mounted. Non-V30 compiled behavior is unchanged.

The raw framing locator uses the zlib end marker to recover the exact unpadded pack length even if the CRC ends with 0xff. Compressed input is capped at 3.5 MiB, metadata at 64 KiB, inflated work at 4 MiB. A fixed 32 KiB dictionary and bounded decompressor allocation avoid retaining the decoded image; CRC and all trailing erased-flash bytes are checked. The ESP32 adapter maps the exact 0x7D0000 / 0x4C0000 partition read-only for the visitor lifetime and unmaps afterward. Its expensive inspect method MUST run away from the UI/radio loop and is not automatically invoked.

This is not map activation or a signed-asset gate. A successful structural probe does not prove data provenance/authenticity. Do not publish a production image, display unverified map data, or interpret host fixtures as national coverage. Next native integration must schedule an explicit low-priority worker, enforce authenticated image provenance, retain bounded render candidates until full validation, and validate hardware memory/MMU/UI/RF timing. Optional internet cache/storage decisions remain separate.
