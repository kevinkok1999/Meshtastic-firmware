# V30 native viewport background job (development candidate)

Map geometry is staged into a caller-owned frame capped at 512 primitives, with Web Mercator projection to a bounded 320x240-equivalent surface. If density exceeds capacity, higher-priority boundary/place/major-road layers are retained; the result explicitly returns Truncated. Full geometry validation must complete before nonzero primitive count is published. Corrupt/cancelled frames expose zero primitives. The tests use the actual pack builder fixture, not a map screenshot or national coverage proxy.

MapProgress adds cooperative checkpoints during raw zlib framing, CRC/padding checks, pack CRC, feature scan and long feature point/segment loops. NanoMapJob is an ESP32 boot-lifetime worker with a single latest-request queue and one result queue. It runs at priority 1 on core 0 and vTaskDelay(1) at checkpoints; UI can submit or take without blocking. Every request gets a nonzero generation token; superseded work is discarded. No LVGL APIs run in the worker. The result is immutable for the consumer until it calls release; visible drawing must occur on the UI owner.

The worker refuses to start without an explicit authorizer. No trust anchor, authorized preview mode, UI hook, vendor GPS-fix integration, map tile replacement or production signing policy is installed here. The compile proves only source compatibility, not timing or memory on live hardware. Required next step: provision the signed asset trust gate, bind the Map tab to the worker using generation-safe rendering/panning/zoom, display provenance/truncation/coverage and distinguish default country center from actual GPS fix/last-known location. Keep existing raster path when no raw image is present. Test memory/MMU/RF coexistence on stock T-Deck Plus before activation. No automatic map formatting or user partition writes are used.
