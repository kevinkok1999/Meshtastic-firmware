# MeshOffGridNL V30 PRO — development specification
Date: 2026-11-16 | Status: DESIGN / NOT BUILT / NOT RELEASED

## Intent
Deliver a successor to V29 PRO that objectively improves emergency messaging, RF reliability and usability. Deliver MeshMap Nano with out-of-box nationwide European Netherlands coverage on stock LILYGO T-Deck Plus without needing any microSD card, Internet, phone or customer configuration. Preserve the existing V29 release and all historical artifacts; do not publish V30 until gates below pass.

## Frozen inputs
- Development baseline: Meshtastic-firmware 18b9f4d4c00c372b5d458c4fbb8c9779f80c6b91 (V29; includes later wallpaper test).
- Released V29 test source f38a93e142f2e1002e412de75f760c606d10bd9d is immutable. Latest baseline changes from that source are workflow and wallpaper-test changes only.
- WadaMesh 6fe6b9f06332708b6ed0cc78958017d0dcc9e35d; MeshCore fork ALLFATHER-BV/meshcomod core-v1.17.4. Resolve tag to immutable SHA and verify actual checked-out dependency before compiling.
- 16 MiB flash; 8 MiB PSRAM; display 320x240; single SX1262 (22 dBm conducted hardware ceiling), shared SD/TFT/LoRa SPI. Preserve partition offsets app0/app1 size 0x3E0000 each, tiles 0x4C0000 at 0x7D0000, SPIFFS 0x360000 at 0xC90000. Target app headroom >=256 KiB. Do not take user data/OTA slots for maps.
- P1 Pro V8 is a BLE companion, NOT a proven autonomous V29/V30 storage repeater. Keep native V28 chat compatibility; separate opt-in relay firmware only after tests.

## Hard requirements / priorities
F01 Transport: the pinned RAW_CUSTOM receive path handles direct routing, not sendFlood. Test actual core packet dispatch, then introduce a capability-gated direct/zero-hop adapter; native V28 DM, group and raw unrelated traffic remain unchanged. RF enqueue, actual TX and verified recipient receipt are different states. Never claim 112 called or official alert.
F02 Persistence: durable local outbox/inbox, atomic journal and commit/readback, bounded replay tombstones keyed by full origin plus message ID; queue-admission before seen marker; acknowledgement verified against intended recipient. Do not drop accepted critical messages silently. Explicit storage failure; old identity/contact material remains internal.
F03 Crypto: retain reviewed AES-GCM and Ed25519; audit key derivation, direction separation, entropy with Wi-Fi/BLE off, nonces across reset, authenticated immutable expiry/carry policy; TTL=0 rejected, mutable relay age untrusted, no claim of exact expiration without trusted time. Full-key trust check, stranger/known labels, no untrusted priority escalation. Metadata not anonymous. Never implement custom cryptographic primitives.
F04 Portal: AP credentials per session, explicit local approval for privileged emergency actions, POST-only, origin/host validation, non-query 128-bit token, bounded nonblocking parser, safe prior power state restoration. No private key exposure.
F05 Radio: all transmit paths (native, emergency, retries, ACK, timeout) under one measured airtime governor; default internal ceiling 8% rolling 3600s in verified 869.4–869.65 profile, never treat emergency priority or channel hopping as exemption. Validate applicable national/European conditions and actual ERP/emissions, conservative cold-start budget. Retain 869.618/BW62.5/SF8/CR4/5 compatibility only until lawful test evidence; 750 Hz nominal upper guard needs spectral check. Candidate alternative profile requires coordinated rollout, not silent tuning. No out-of-band transmissions, jamming, unauthorized power or interference. Single radio cannot listen simultaneous profiles.
F06 Reliability/power: single owner of radio/queue state, nonblocking display/flash/map work, no spectrum sweep stealing radio in emergency mode. Real battery power measurement, preserve RX availability and existing safe idle strategy; 192h external-energy target only, not proven stock battery. 
M01 Maps: no mandatory external card. Factory internal map pack includes all 12 European NL provinces, islands, boundary-defined extent; baseline municipalities, cities, towns, prioritized roads/water and offline place lookup. Target actual road detail comparable to zoom 15–16 where compressed dataset permits, UI zoom 3–19; distinguish actual detail from overzoom; no all addresses/buildings, full turn-by-turn or Google equivalence claim. Do not advertise complete street coverage without measured completeness.
M02 Budget: tiles partition 4.75 MiB; keep >=320 KiB free, pack <=3.5 MiB candidate, optional local cache <=512 KiB with eviction (confirm filesystem overhead). Preserve immutable map pack and fall back without silently formatting. No user data or map asset on SD required. Pack data and firmware separated; install map image via explicit validated offset only on V30 setup, then OTA firmware updates preserve map. No map bytes over LoRa.
M03 Provenance: produce maps from licensed OSM raw extract or official PDOK sources; never bulk fetch public tile server or Google Maps. Include data date, license, geographic extent, feature/zoom inventory, pack and index SHA256, signature against pinned separate verification key. No secret key in repo. Visible attribution, ODbL obligations/redistribution, credits retained offline.
M04 Map behavior: offline first boot default Netherlands overview without fake GPS, local GPS fix+age+accuracy and last-known separate. Sharing off by default; explicit encrypted recipient-bound location share. Place search, zoom/pan, marker/favorites, map health. Streaming decode, bounded allocation, cooperative render, no blocking RF deadlines. Missing/corrupt pack retains chat and emergency; no implicit format. Optional internet local cache only with consent, never listed as offline country detail.
X01 Future staged capabilities: multi-transport ESP-NOW/BLE/local Wi-Fi only on validated supported hardware; one logical message identity, authenticated transport, no auto insecure fallback, no P1 Wi-Fi claim. Family Shield, opt-in coverage maps, local phone map portal, signed bulletins, practice mode strictly separate from real alerts. These follow F01–F06 and M01–M04; independently feature gated.
X02 Commercial gates: no production installer/release until real hardware pair/triple tests, P1 native interoperability, 72h combined soak, 192h external energy measurement, RF conformity and recovery, pack size/coverage/latency demonstrated. Separate software CI and hardware gates.

## Approaches considered
A: patch V29 in place — rejected, risks existing immutable test release and lacks insulated gates.
B: new V30 branch, additive V30 overlays on V29 baseline, successive independently verified gates — chosen.
C: new radio/board plus GB map storage — rejected for V30 stock-hardware target; future product option only.
Mapping: raster only (unacceptable detail/size), compact vector only (new renderer and data selection), hybrid permanent compact vectors + optional bounded local raster cache (chosen). No external card required.

## Acceptance matrix
A1 paired actual RF emergency message/verified ACK (including zero-hop, retry, legacy DM/group); A2 three-node separated mesh carry with reboot; A3 abnormal queue/replay/invalid signature, expiry, unknown identity, nonce reset and power-cut fault injection; A4 rolling hour measured airtime, RF profile compatibility/conformity; A5 72h mixed RF/map load, no false status, controlled memory and UI; A6 map pack offline first boot NL, 12 provinces and sampled islands/borders, feature coverage report and bytes, no card; A7 no-fix/stale GPS/privacy, corrupted or absent pack, OTA preservation and safe recovery; A8 192h externally powered measured workload; A9 exact flash manifest, hashes, board and signed asset, installer gated. Any unverified item remains UNKNOWN/BLOCKED and marketing claims match evidence.
